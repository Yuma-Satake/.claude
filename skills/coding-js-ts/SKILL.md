# JavaScript / TypeScript コーディング規約

## JS/TS共通

### JSDoc

- JSDocを必ず記載すること（example等、詳細すぎるものは不要/既存にコメントが存在する場合には書き換えない）
- JSDocは1行だけであっても、必ず複数行で記載すること

### 関数型プログラミング / イミュータビリティ

- 関数型プログラミングを優先：`map`/`filter`/`reduce` を `for`/`while` ループより優先
- イミュータブルな操作：スプレッド演算子（`...`）を使い、`push`/`splice` などの破壊的メソッドを避ける
- 配列に対して破壊的な操作（`push`/`pop` など）を禁止し、代わりに非破壊的な操作（`map`/`filter` など）を使用すること

### 変数 / 定数

- `const` を優先し、`let`/`var` の使用を禁止する

### 制御フロー / 可読性

- `else if` を避けること
- 早期リターンでは、1行で収まる場合、中括弧を省略して記載すること
- 三項演算子が2つ以上ネストする場合、即時関数（IIFE）を使用して可読性を確保すること

### 関数定義

- 関数はfunctionではなくアロー関数で定義すること（既存の関数定義に関しては変更しないこと）

### 非同期処理

- 非同期処理では `async`/`await` を優先し、Promiseチェーンを絶対に使用しないこと（既存にPromiseチェーンが存在する場合は変更しないこと）

### 文字列

- 文字列を結合するときには、テンプレートリテラルを使用すること

### エラーハンドリング

- catchブロックのエラーログには `error instanceof Error ? error.message : "Unknown error"` を使用し、errorオブジェクトを直接出力しないこと
- 外部APIのエラー詳細はサーバーログに留め、クライアントには汎用メッセージのみ返すこと

## TS固有

### 型定義

- 型の定義においては、`interface` より `type alias` を使用すること（既存のプロジェクトで `interface` が多く使用されている場合は `interface` を使用）
- `enum` は使用せず、`as const` オブジェクト + union型を使用すること（値の一覧が必要な場合には、Object.values() を使用）
- `as const` オブジェクトの値を使用する際は、文字列リテラルを直接書かず、必ずオブジェクトのプロパティを参照すること（例: `"active"` ではなく `Status.Active`）

### 関数の型

- 関数の型定義は引数と返り値共に必ず型定義を行うこと
- 返り値の型定義は共通化の必要がない場合インラインで定義すること（例: `const fun = (): { id: string } => ...`）

### 型設計

- 型推論が効く場合でも明示的な型アノテーションを優先すること
- ジェネリクスを活用して再利用可能で型安全なコードを書くこと
- 型ガードを使って安全に型を絞り込むこと
- 型ガードの結果を別のboolean変数に代入して条件式に使っても、その変数経由では元の変数の型は絞り込まれない（ナローイングが伝播しない）。絞り込みを効かせるには同じ式内で再度nullチェック等を書くこと（例: `const g = x != null; const y = g && x.n > 0;` は `x.n` で型エラーになりうる。`const y = x != null && x.n > 0;` のように1つの式にまとめる）
- 動的な型変換にはMapped Typesを活用すること

### その他

- classの使用を禁止する。代わりに関数とオブジェクトを使用すること
- `any`/`as`/`unknown` など、型の安全性を損なうような記述の使用を禁止する
