# commit スキル 補足手順(エッジケース)

発生頻度は低いが、発生した際に必要な詳細手順をまとめる。該当状況になったときだけ参照する。

## リモート同期時にuntrackedファイルがpullと衝突する場合

Step 1.5 の同期手順中、untrackedファイルがリモートと衝突して `git pull` が失敗した場合の対処。

1. 衝突している当該ファイル・ディレクトリをバックアップする
2. 当該ファイル・ディレクトリを削除する
3. `git pull` を再実行する
4. pull完了後、バックアップの内容を確認し、必要な変更を手動でマージする

## 変更を複数ブランチ(複数PR)に振り分ける場合の注意

Step 3 で分割した単位をそれぞれ別ブランチにコミットして別PRにする場合、対象外ファイルを退避する手段として `git stash push -- <pathspec>` を使わない。この操作は指定ファイルの差分だけを退避するわけではなく、ワーキングツリー全体の状態を1つのstashとしてスナップショットしたうえで、pathspecに一致するファイルのみをワーキングツリー上でHEAD状態に戻す（他のファイルはそのまま残る）。そのため、このstashを別ブランチでpopすると、退避時点の全ファイルの差分が復元されてしまい、他の単位の変更まで意図せず混入する。

代わりに以下の手順を使う。

1. 元のブランチ（全単位の変更が未コミットで存在する状態）で、1つ目の単位のファイルのみ `git add` してコミットする
2. 分岐元のベースブランチに `git switch` で戻る（他単位の未コミット変更はそのまま working tree に残る。1つ目の単位のファイルはコミット時点のHEAD内容に戻る）
3. `git switch -c <branch2>` で2つ目のブランチを作成する
4. 2つ目の単位のファイルを `git add` してコミットする

## 1つ目の単位を既にコミット・push済みの状態から、残りをさらに別ブランチに分割する場合

上記の手順は「両方の単位が未コミットのまま同じブランチに存在する」状態を前提にしている。1つ目の単位を先にコミット・push・PR化した後で、2つ目の単位（未コミットのまま残っている）を別ブランチに分けたい場合は手順が異なる。

1. 元のブランチ（1つ目の単位はコミット済み、2つ目の単位は未コミットで残っている状態）で、`git stash push -u -m "<一意なタグ>"` で2つ目の単位を退避する
2. 1つ目の単位のブランチを土台に、`git switch -c <branch2>` で2つ目のブランチを作成する（1つ目のコミットを含む状態から分岐する）
3. `git stash apply <sha>` で退避した変更を適用する。1つ目のブランチで新規追加したファイルと2つ目の変更が重なる場合、そのファイルが既にコミット済みの内容と同一なら `<file> already exists, no checkout` という警告が出るが無視してよい。他の追跡ファイルの変更が `Auto-merging` で正しく復元されていることを `git status --short` で確認する
4. 残った差分（1つ目のブランチのコミットには含まれない、2つ目の単位固有の変更）だけが反映されていることを `git diff` で確認してからコミットする
5. 2つ目のブランチのPRは1つ目のブランチをbaseにして作成し、1つ目がマージされたらbaseをベースブランチに変更する旨をPR本文に明記する

## 1ファイル内の複数hunkが別々のコミット単位に分かれる場合

Step 3で「同一関数・同一hunk内で複数の論理的関心事が隣接行に混在し、hunk単位でも分離できない」場合は分割を諦めるが、hunk単位では分離できる（変更箇所が離れた行にあり、hunkとして独立している）場合はこの手順で分割する。ファイルを手動で中間状態に再構築しない。

1. `git diff -U1 -- <file>` でhunkの境界を確認し、各hunkがどのコミット単位に属するかを判定する
2. `printf 'y\ny\nn\n...\n' | git add -p -- <file>` で、手順1の判定順にhunkごとの`y`(この単位に含める)/`n`(含めない)をまとめて流し込み、対象単位のhunkだけをステージする
   - hunk数と`y`/`n`の個数が一致しない場合、git側の実際のhunk分割（デフォルトのcontext行数）が事前確認時の想定と異なっている可能性がある。出力されるhunkの内容を確認し、想定と食い違っていたら`q`で中断してやり直す
3. `git diff --cached --stat -- <file>` と `git diff --stat -- <file>`（ステージ済み/未ステージそれぞれ）で、意図した単位だけがステージされているか確認してからコミットする
4. 残りのhunkは次のコミット単位の`git add`でまとめてステージすればよい（未ステージのまま working tree に残っている）

## ファイルのリネーム・削除・移動を含む変更をステージする際の参照確認

Step 4 でステージ内容にファイルのリネーム・削除・移動が含まれる場合、旧パス・旧名称への参照が残っていないかをgrepで全件確認する。

確認対象はドキュメント（README・docs配下・ガイド類）、skill/agent定義内の相互参照（`Skill X をロードする` など名前で呼ばれている箇所）、issue/PRテンプレート、CIワークフロー、設定ファイル内のパス・キー指定。1層だけ確認して終わらせず、未更新の参照は修正して同じコミットに含める。
